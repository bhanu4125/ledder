# LedgerLine threat notes

This is a prototype threat assessment. It records controls that exist, the attack surface a reviewer can exercise, and evidence status. Do not treat unexecuted tests as proof.

| Threat / probe | Implemented control | Evidence | Current result / gap |
|---|---|---|---|
| Double-spend and concurrent withdrawals: submit 50 withdrawals against one balance | `TransactionService` looks up the system account id without loading a stale entity, then locks all participating account rows in ascending id order, rechecks balances while locked, and updates both accounts in one transaction; database rejects negative balances | `LedgerLineIntegrationTest.concurrentWithdrawalsNeverOverdrawAnAccount`; live 50-request Compose smoke test | The Testcontainers test is written but skipped because Testcontainers cannot discover the running Docker Desktop daemon. The separate live smoke test passed: 5 withdrawals returned 201, 45 returned 409, none returned 500, and the balance ended at $0.00. |
| Duplicate/replayed money request | Required UUID `Idempotency-Key`; database transaction-scoped advisory lock serializes a key; request hash conflict gives 409; response is stored with ledger writes | `LedgerLineIntegrationTest.duplicateTransactionIsReturnedOnceAndChangedBodyConflicts` | Sequential and concurrent replay tests are written; not executed without Docker. |
| IDOR on account details/source | Every holder account read/movement loads the row and compares the owner with the authenticated user; known foreign ids return 403 | `LedgerLineIntegrationTest.ownershipAndRoleControlsRejectCrossAccountAndAuditorWrites` | Test is written; not executed without Docker. |
| Role escalation / forged JWT | Signature and issuer are validated before claims reach method security; controller methods enforce roles | `LedgerLineIntegrationTest.tamperedJwtCannotEscalateRole`, `LedgerLineIntegrationTest.invalidAmountsAndExpiredTokensAreRejected` | Tampered and expired token tests are written; explicit "business method not entered" instrumentation is still missing. Role claims can remain stale for at most 15 minutes after admin changes. |
| SQL injection | Persistence reads use Spring Data JPA; native SQL is static or parameterized JDBC (including advisory locks); request values are not concatenated into SQL | Manual review of repositories/services | No automated SQL-injection test yet. |
| XSS | React escapes rendered text; Nginx sends a restrictive CSP; no user-controlled HTML rendering or third-party fonts/scripts are used | `docker/nginx.conf` and React render paths | No browser-based XSS test yet; CSP needs review if new external assets/features are added. |
| CSRF against refresh/logout | Access tokens are accepted only in the Authorization header; refresh is HTTP-only, SameSite=Strict, scoped to `/api/auth`, and refresh/logout require an exact `Origin` match | `AuthController` cookie/origin checks | No automated browser CSRF test yet. Same-site reverse-proxy deployments must configure the exact UI origin. |
| Brute-force login | BCrypt cost 12; generic auth failure; five failures within 15 minutes trigger escalating lockout; per-IP/per-email process-local rate limits | `LedgerLineIntegrationTest.loginFailuresAreGenericAndLockTheAccount` | Test is written; not executed without Docker. Counters are in-memory and do not coordinate across instances. |
| Ledger/audit history modification | SHA-256 chained rows; ledger verify names the first broken row; Compose runtime role lacks UPDATE/DELETE on both tables | `LedgerLineIntegrationTest.tamperingWithHistoricalLedgerDataReportsTheFirstBrokenRow`, `LedgerLineIntegrationTest.runtimeDatabaseRoleCannotUpdateOrDeleteAppendOnlyTables`, `scripts/check-append-only.ps1`; live Compose verification | The Testcontainers tamper/grant tests are skipped because of Docker discovery failure. The live append-only script passed all four UPDATE/DELETE denial checks, and ledger verification returned `VERIFIED` for 18 rows. There is no audit-chain verification endpoint yet. A privileged database owner can still rewrite and recompute history. |
| Negative balance / amount overflow | Bean Validation (`> 0`, 2 decimal places, bounded precision), balance check under row lock, and PostgreSQL `CHECK (balance >= 0)` | Migration `V1__initial_schema.sql`, transaction DTO/service, `LedgerLineIntegrationTest.invalidAmountsAndExpiredTokensAreRejected` | Negative/zero/overflow API tests are written; not executed without Docker. |
| Unauthorized auditor writes | `@PreAuthorize` restricts transaction/approval mutations to account holders/authorisers respectively; admin/auditor read access is separate | `LedgerLineIntegrationTest.ownershipAndRoleControlsRejectCrossAccountAndAuditorWrites` | Test is written; not executed without Docker. |
| Audit event omission | Authentication failures, successful login/logout, user/account changes, transaction decisions, and verification are appended to a separate hash chain | `AuditService` and call sites | No verifier for the audit chain, and malformed/forged JWTs and rate-limit events are not yet appended to the audit chain. There is no exhaustive test that every future mutation emits an event. |

Known operational gap: local single-user database development does not automatically install restricted runtime grants. The guarantee applies to a fresh Compose volume. The DB owner, Docker host administrator, or a compromised deployment secret can change grants and data.
